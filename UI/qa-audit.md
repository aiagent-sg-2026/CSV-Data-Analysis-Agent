## Confirmed issues fixed

1. **History lost Pi cards after reselecting the CSV.** A deterministic cleaning step changed the prepared table version while analysis evidence still referenced the source table. Restore now verifies the original file and both relevant versions, reproduces preparation when needed, and restores saved cards/report only when evidence matches. A wrong-file attempt keeps the saved record available.
2. **Data Explorer clipped on mobile.** A query grid demanded 571px inside a 390px dialog. Its grid track and children can now shrink; the measured content width is 366px. [Before](data-explorer-mobile-before.png) / [after](data-explorer-mobile-after.png).
3. **Upload action was inaccessible by keyboard.** A styled label became a real button with a 44px target. Enter opened the picker in the browser. The control resets the input so users can select the same file again. [Before desktop](upload-baseline-desktop.png) / [before mobile](upload-baseline-mobile.png) / [after mobile](upload-after-mobile.png).
4. **Historical query status was misleading.** Some saved AI queries keep counts but no preview rows. The empty grid and history badge now explicitly state that the preview is unavailable.
5. **Several mobile controls were too small.** Upload and Settings actions now have 44px minimum targets; Settings dialog fits within a 390px viewport. [Settings after](settings-mobile-after.png).
6. **Card count was shown as a decimal.** `row_count` now renders as an integer (`30`, not `30.00`). The Advanced header icon is now distinct from Data Explorer, and the upload empty state is vertically centered against the available height.

## Verification limits

- The full HDB demo was tested for import, initial analysis, and Pi card creation. The other UI journeys above were tested with the synthetic CSV, not repeated against every row of the full demo.
- PDF generation stopped at the browser print action; no produced PDF was inspected.
- Every possible CSV structure and downloaded export artifact was not exercised.

## 2026-09-29 average-card retest

The live 27-Town HDB card exposed a data-semantics defect: each town average was presented as a share of the sum of averages, Top N could create a synthetic `Others` sum of averages, and the summary reported that sum as a total. The chart also compressed all 27 Towns into a dense combo view. [Desktop baseline](avg-card-baseline-desktop.png) / [mobile baseline](avg-card-baseline-mobile.png). A separate [visual proposal](avg-card-visual-proposal.md) uses illustrative placeholder values, not HDB results.

The React source now keeps Top N averages as individual groups, omits the misleading `Others`, share, and total claims, and defaults dense non-temporal average cards to a readable horizontal bar chart. All groups use a keyboard-scrollable chart region; PNG export temporarily expands it. Average time trends retain line/area charts. SQL table-mode cards now retain their true aggregate type; older cards without one use an explicit unknown-aggregation message.

In the in-app browser, a synthetic 135-row CSV completed initial analysis 9/9, and Pi saved a new average-price card with all 27 Towns. Its Top 8 view showed the independently expected averages from 572,000 down to 502,000 without percentages or `Others`. Switching to All showed 27 groups and a 27-row table whose transaction counts summed to 135. On a 390px viewport the document width remained 390px, and the long chart region measured 540px visible against 1,106px scroll height with keyboard focus. After loading the final static build and reselecting the original CSV, saved analysis and Pi card restored, All groups ranked highest-first, and older missing-aggregation cards displayed the neutral message. [Desktop after](avg-card-after-desktop.png) / [mobile after](avg-card-after-mobile.png). The export menu responded, but the in-app browser did not return a download-file event for attempted PNG/CSV exports; those artifact files remain unverified.

The first public deployment also completed the same 135-row analysis 9/9, and Pi saved a 27-row card. Its All table again summed transaction counts to 135. That run revealed two more presentation defects: a `count` card showed `135.00` in its legend, and a SQL table-only card described itself as table-first while displaying a one-row chart first. Count legends now format whole numbers. Table-only plans open their table by default and omit chart controls and chart-only export. The executor had silently overwritten the planner's table visibility flag; a regression test now verifies both the planner and final card request. A fresh local in-app browser analysis completed 9/9, showed its one-row count results as visible tables without chart controls, and Pi saved a 27-Town count card with integer `5` per Town; All exposed 27 real groups and a total of 135. [Local Pi count and table-first screenshot](pi-count-and-table-first-local.png). The source suite passed 367 files / 3,445 tests, TypeScript and lint passed.

The second public E2E confirmed the deployed table-first result and a Pi-created 27-Town count card. It also exposed a stale `"Others" hidden` badge after switching that card to All. The summary now shows that badge only when Top N actually folds groups. The All-scope regression checks both the badge and explanatory line.

## 2026-09-29 offline import QA

On the production preview, an offline 90-row HDB-shaped CSV import waited about 60 seconds for two optional provider timeouts and then launched cloud analysis despite the browser still being offline. A late consent decision could leave the imported dataset marked as a provider failure (0/9). The service-worker shell and local Data Explorer remained available.

The optional AI intake-boundary, report-context, and structure-proposal helpers now return to their deterministic paths immediately while offline. The import orchestrator marks the local dataset ready and pauses the Pi analysis before dispatch; it does not record an offline condition as a declined cloud-consent decision. The results panel offers **Retry analysis** with offline-specific guidance. Retrying while offline does not start a provider request. The PWA banner no longer promises automatic resumption of an analysis that has not started.

In a fresh in-app browser production build, the same public sample reached **Local import ready (1/1)** in under five seconds with 90 prepared rows and no provider timeout warnings. Data Explorer still displayed 25/90 local rows and recorded zero queries. At 390px the document width was 390px, and [the mobile screenshot](offline-import-after-mobile.png) shows the offline banner, local result, and retry action. After reconnecting, Retry opened the Shared GPT Server consent dialog and completed Pi initial analysis 9/9 with two Verified cards and no browser error logs. The run reported a limitation because AI summary synthesis exceeded its time budget; card generation still completed. This worktree remains local and has not been deployed to Pages.

## 2026-09-29 HDB block identifier QA

The first reconnected run produced two Verified cards, but one summed the numeric-looking HDB `block` code by Storey Range and Flat Type. Its executive KPI showed 30,588 as a “Total Block,” which is mathematically computable but has no business meaning. The shared column role classifier and query registry now treat `block`, `block_no`, `block_number`, and `block_id` as dimensions even when the sampled profile calls them numerical; the final SQL governance rejects `SUM(block)`. This changes a reusable semantic primitive and does not modify the OODAE runner.

In a new production-build in-app browser run on the same 90-row public CSV, initial analysis completed 9/9 with two Verified cards: **Top Street Names by Sum Resale Price** and **Sum Resale Price by Town**. Neither aggregated `block`. Independent CSV aggregation matched displayed values: JURONG WEST 4,230,000, TAMPINES 3,459,000, and TOH YI DR 1,587,000. [Corrected card screenshot](hdb-block-guard-after-desktop.png). The browser had no error logs. These cards query a top-10 subset for presentation, so their displayed “overall” is scoped to that subset rather than all 90 rows.

## 2026-09-29 offline History restore QA

Reloading a completed 90-row report and reselecting its source CSV while offline previously started cloud cleaning despite the offline state. It could spend over 100 seconds in SQL precheck and leave the saved cards unavailable. The import now stops before replacing the saved analysis when its evidence version needs cloud-assisted preparation. In the in-app browser it displayed a specific reconnect message immediately, and the saved History entry remained available. [Offline guard screenshot](offline-history-restore-guard-desktop.png).

The online retry exposed two separate version-bound restore defects. The saved transformation program omitted the deterministic removal of fully empty columns, so strict replay rejected a valid source. Replay now tries that legacy deterministic step only after the normal replay misses and accepts it only when the final hash exactly equals the committed output version. The restore then used the source version where it needed the cleaned version; it now resolves the prepared structure through the same helper used by Pi before comparing evidence versions. The source fingerprint and the saved source and analysis version hashes must all match before cards are reused.

In a fresh production-build in-app browser run, the public CSV restored in about 20 seconds with **Saved analysis restored (1/1)**, two visible Verified cards, and the same card IDs as the saved record. The source version and analysis version matched the saved hashes; Pi did not start a new 9-stage analysis. No browser exception was recorded. [Restored desktop screenshot](history-restore-after-desktop.png). From the restored cards, **Generate Analyst Report** completed and changed to **Open Report**. The browser safety policy blocked navigation when opening it and forbade a workaround, so the report preview and downloaded artifact were not verified. The root deployment and public Pages site have not been updated with this QA worktree.

The local production preview at 390px measured 44px for all three sort choices, the previous-version toggle, More actions, Resume analysis, and Clear all; document width remained 390px. The previous-version button announced expanded/collapsed state. Both an upper and a lower row menu were fully visible. The final source renders the menu inside the dialog, outside the list scroller; its three actions measured within the dialog at both sizes, and clicking outside dismissed it.
